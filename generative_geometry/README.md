# Generative Geometry

This directory preserves the Generative Geometry experimental sequence associated with the Generative Principle and Universal Recursion Principle research programme.

## Scope

The source-focused snapshot contains the original supplied Pilot 3 implementation and the Pilot 3b and Pilot 4–4i implementations, together with their pre-run protocols where applicable, reports, run metadata, and run logs. The original uploaded implementation is preserved separately from the strengthened Pilot 3b version.

`artifact_manifest.csv` inventories the complete experimental artifact set, including raw result tables, proposal histories, candidate scores, figures, smoke-test outputs, and complete-result archives. Each record includes the file size and SHA-256 digest. Those large tables and binary artifacts are catalogued but are not included in this source-focused commit.

## Experimental sequence

- **Pilot 3:** original relational-curvature active-sampling implementation.
- **Pilot 3b:** stronger deterministic controls, paired comparisons, nested budgets, and noise audits.
- **Pilot 4:** supplied higher-order relational representations.
- **Pilot 4b:** autonomous constructor discovery.
- **Pilot 4c:** expression refinement within retained lineages.
- **Pilot 4d:** permutation-randomized geometry and multi-step scaffolding.
- **Pilot 4e:** matched mechanisms for crossing immediate-score valleys.
- **Pilot 4f:** frozen constructors and permutation-invariant integration.
- **Pilot 4g:** search aligned with invariant development scoring and final integration.
- **Pilot 4h:** terminal objective reselection with identical candidates and integration.
- **Pilot 4i:** multi-constructor retention and complementary integration.

## Interpretation boundary

These are finite synthetic computational experiments. They do not by themselves establish open-endedness, cognition, consciousness, biological or social conclusions, metaphysical laws, or universal architectural necessity. Reports preserve negative results, heavy tails, family-specific failures, and the distinction between exploratory and confirmatory analyses.

## Reproduction

Each pilot directory contains its implementation and report. Later pilots may import the preceding validated implementation; retain the sibling directory layout when reproducing them. In particular, Pilot 4i imports Pilot 4h from `../pilot4h`. Dependencies and exact software versions are recorded in the metadata files and reports.

The preserved protocols are pre-run commitments and must not be edited retrospectively to match outcomes. The reports distinguish encountered, parent-retained, output-retained, integrated, and effectively useful structure; forced exact-area inclusion in Pilot 4i is diagnostic rather than autonomous discovery.
